# Core Responsibilities

Before writing code, always:

- Understand the requested task.
- Read the relevant documentation.
- Understand the existing implementation.
- Verify that the requested feature belongs within the scope of this repository.
- Preserve the existing architecture and design language.

Never make assumptions.

If requirements are unclear, ask for clarification before implementation.

---

# Implementation Rules

While working on this project, you must:

- Follow every coding standard.
- Respect the project architecture.
- Preserve the existing UI language.
- Follow all animation guidelines.
- Follow all database rules.
- Follow every AI workflow rule.
- Avoid introducing unnecessary complexity.
- Prefer existing components over creating new ones.
- Avoid duplicate implementations.
- Keep the codebase clean and maintainable.

---

# Scope

This repository is **only** responsible for the Examinr.ai waitlist.

Do not implement features belonging to the main Examinr.ai platform.

If a request falls outside the scope of this repository, explain why before proceeding.

---

# Dependencies

Do not introduce new dependencies unless absolutely necessary.

Always verify that the existing stack cannot already solve the problem.

If a new dependency is required, explain the reasoning before installing it.

---

# Code Quality

Every contribution must be:

- Production-ready
- Type-safe
- Readable
- Responsive
- Accessible
- Consistent with the existing design system

Never leave unfinished implementations.

# Before Completing Any Task

Before considering a task complete, verify that:

- The implementation follows all project documentation.
- Existing functionality remains intact.
- No unnecessary code has been introduced.
- Naming conventions are respected.
- The project remains buildable.
- Documentation has been updated if necessary.

# Guiding Principle

This project values:

- Clarity over cleverness.
- Consistency over personal preference.
- Simplicity over unnecessary abstraction.
- Long-term maintainability over short-term convenience.

When in doubt, follow the documented standards rather than inventing new patterns.
